How a contribution happens.

We keep it simple and respectful of the project we're helping. The upstream maintainers set the rules; we follow them.

Fork

We find an open issue, read the contributing guide, and make our own copy to work in.

git fork upstream/project

Fix

Small, focused changes with tests and clear commit messages. Two of us review before anything leaves the group.

git commit -m "fix: ..."

Send it back

We open the pull request, answer feedback, and stay on it until it lands or the maintainers say no thanks.

git push && open PR

Maintainers come first

We ask before starting large changes, and we never open a pull request that creates more review work than it saves.

Everything stays public

Our patches, our reviews and our mistakes are all in the open. You can read exactly how we work.
